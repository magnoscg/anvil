# SwiftData Integration Guide

> Patterns for SwiftData persistence in Clean Architecture (iOS 17+).
> Related skills: `/axiom:audit core-data`, `axiom:axiom-swiftdata`, `axiom:axiom-swiftdata-migration`
> Axiom complementa: VersionedSchema, custom migrations, CloudKit sync

> **`Example/` does not use SwiftData.** It has no `@Model` types, no `ModelContainer`, no `Core/Persistence/` and no `App/DI/` folder; the only persisted state is the navigation path (`@SceneStorage` in `RootNavigationView`). Nothing in this guide describes code that exists in `Example/`.
>
> The stack described here is an **optional Anvil template**: `anvil init` generates it only when the "SwiftData" option is selected (off by default). The template lives in `templates/swiftdata/` and produces `Core/Persistence/ModelContainerShared.swift`, `Core/Persistence/SwiftDataStack.swift` and `App/DI/PersistenceAssembly.swift`; it also adds a `swiftDataStack` property to `App/Config/AppDependencies.swift` and `.modelContainer(...)` to the `@main` App. Read this guide only when adding SwiftData to a project.

## Overview

SwiftData provides a declarative approach to data persistence. This guide covers how to integrate it correctly with Clean Architecture while maintaining thread safety. The layer rules from `ARCHITECTURE.md` still apply: the repository **protocol** lives in `Domain/<Concept>/Repositories/`, the Impl in `Data/<Concept>/Repositories/`, and every Impl that can fail wraps its work in `DomainError.catching`.

## SwiftData Stack Setup

### ModelContainer Configuration

```swift
// Core/Persistence/ModelContainerShared.swift (generated by the SwiftData template)
import SwiftData

extension ModelContainer {
    static let shared: ModelContainer = {
        let schema = Schema([
            FeatureSDModel.self,
            UserSDModel.self
        ])

        let modelConfiguration = ModelConfiguration(
            schema: schema,
            isStoredInMemoryOnly: false,
            allowsSave: true
        )

        do {
            return try ModelContainer(
                for: schema,
                configurations: [modelConfiguration]
            )
        } catch {
            fatalError("Could not create ModelContainer: \(error)")
        }
    }()

    /// In-memory container for previews and tests
    static let preview: ModelContainer = {
        let schema = Schema([
            FeatureSDModel.self,
            UserSDModel.self
        ])

        let config = ModelConfiguration(
            schema: schema,
            isStoredInMemoryOnly: true
        )

        do {
            return try ModelContainer(for: schema, configurations: [config])
        } catch {
            fatalError("Failed to create preview ModelContainer: \(error)")
        }
    }()
}
```

### SwiftDataStack for Dependency Injection

```swift
// Core/Persistence/SwiftDataStack.swift (generated by the SwiftData template)
import SwiftData

// MARK: - SwiftDataStack

/// Owns the ModelContainer and vends one isolated ModelExecutor per repository.
@MainActor
final class SwiftDataStack {
    // MARK: - Properties

    let container: ModelContainer

    // MARK: - Init

    init(container: ModelContainer = .shared) {
        self.container = container
    }

    // MARK: - Executor Factory

    func makeBackgroundExecutor() -> ModelExecutor {
        DefaultSerialModelExecutor(
            modelContext: ModelContext(container)
        )
    }
}
```

Each repository must receive its **own** executor; never share executors or use `container.mainContext` from background code.

## Thread Safety: Pass IDs, Not Models

### The Golden Rule

> **NEVER pass SwiftData models between actors. Pass IDs instead.**

SwiftData models are bound to their `ModelContext` and are **NOT thread-safe**.

### Wrong vs Right

```swift
// ❌ WRONG: Passing model across actors
@MainActor
class FeatureViewModel {
    func saveFeature(_ feature: FeatureSDModel) async {
        // CRASH RISK: feature is bound to main context
        await repository.save(feature)
    }
}

// ✅ RIGHT: Pass ID, fetch on target context
@MainActor
class FeatureViewModel {
    func saveFeature(_ featureId: UUID) async {
        await repository.save(featureId: featureId)
    }
}
```

### Repository Pattern with IDs

The protocol (`FeatureRepository`) lives in `Domain/<Concept>/Repositories/`; only the Impl below is in Data.

`ModelExecutor` only exposes `modelContext`; it has no `perform { }`. A repository that receives its own executor is an `actor` conforming to `ModelActor`: it stores the injected `modelExecutor` and `modelContainer` as `nonisolated let`, runs on that executor, and uses the protocol-provided `modelContext`. This is exactly what the `@ModelActor` macro generates; writing it by hand lets the Factory inject the executor from `SwiftDataStack`.

```swift
// Data/[Feature]/Repositories/FeatureRepositoryImpl.swift
import SwiftData

// MARK: - FeatureRepositoryImpl

actor FeatureRepositoryImpl: FeatureRepository, ModelActor {
    // MARK: - Properties

    nonisolated let modelExecutor: any ModelExecutor
    nonisolated let modelContainer: ModelContainer

    // MARK: - Init

    init(modelExecutor: any ModelExecutor, modelContainer: ModelContainer) {
        self.modelExecutor = modelExecutor
        self.modelContainer = modelContainer
    }

    // MARK: - FeatureRepository

    func fetchFeature(id: UUID) async throws -> FeatureModel? {
        try await DomainError.catching {
            let descriptor = FetchDescriptor<FeatureSDModel>(
                predicate: #Predicate { $0.id == id }
            )
            return try modelContext.fetch(descriptor).first?.toDomain()
        }
    }

    func save(_ model: FeatureModel) async throws {
        try await DomainError.catching {
            let modelID = model.id
            let descriptor = FetchDescriptor<FeatureSDModel>(
                predicate: #Predicate { $0.id == modelID }
            )

            if let existing = try modelContext.fetch(descriptor).first {
                existing.update(from: model)
            } else {
                modelContext.insert(FeatureSDModel(from: model))
            }

            try modelContext.save()
        }
    }
}
```

The executor must wrap a context of the same container (`SwiftDataStack.makeBackgroundExecutor()` creates a `DefaultSerialModelExecutor` over `ModelContext(container)`). Only Domain models (`FeatureModel`) leave the actor; `FeatureSDModel` never does.

As with any repository, each method body is wrapped in `try await DomainError.catching { ... }` so it throws only `DomainError` or `CancellationError` (see `ARCHITECTURE.md`). `catching` runs in the caller's isolation (`#isolation`), so the closure can use the actor's `modelContext` directly.

## ModelExecutor for Background Operations

### Why ModelExecutor?

- `ModelContext` is **NOT** thread-safe
- Main context blocks UI during heavy operations
- `ModelExecutor` provides isolated context for background work

### DefaultSerialModelExecutor

```swift
// Features/[Feature]/DI/FeatureFactory.swift (private helper)
static func makeRepository(dependencies: AppDependencies) -> FeatureRepository {
    FeatureRepositoryImpl(
        modelExecutor: dependencies.swiftDataStack.makeBackgroundExecutor(),
        modelContainer: dependencies.swiftDataStack.container
    )
}
```

### Alternative: @ModelActor (iOS 17+)

`@ModelActor` provides a cleaner alternative to manual `DefaultSerialModelExecutor` setup:

```swift
@ModelActor
actor FeatureModelActor {
    func fetchAll() throws -> [FeatureModel] {
        let descriptor = FetchDescriptor<FeatureSDModel>(
            sortBy: [SortDescriptor(\.createdAt, order: .reverse)]
        )
        return try modelContext.fetch(descriptor).map { $0.toDomain() }
    }

    func save(_ model: FeatureModel) throws {
        let sdModel = FeatureSDModel(from: model)
        modelContext.insert(sdModel)
        try modelContext.save()
    }
}
```

**When to use each**:

| Approach | Use When |
|----------|----------|
| `@ModelActor` | Simpler setup, actor-based repository, less boilerplate |
| Hand-written `ModelActor` conformance + injected `DefaultSerialModelExecutor` | Need to inject the executor from `SwiftDataStack` (the repository pattern above) |

Both approaches are correct. `@ModelActor` is the modern Apple recommendation for most cases.

### Custom ModelActor (Advanced)

For complex operations, create a dedicated actor:

```swift
// Data/[Feature]/Actors/FeaturePersistenceActor.swift
@ModelActor
actor FeaturePersistenceActor {

    func fetchAll() throws -> [FeatureModel] {
        let descriptor = FetchDescriptor<FeatureSDModel>(
            sortBy: [SortDescriptor(\.createdAt, order: .reverse)]
        )
        let sdModels = try modelContext.fetch(descriptor)
        return sdModels.map { $0.toDomain() }
    }

    func save(_ model: FeatureModel) throws {
        let sdModel = FeatureSDModel(from: model)
        modelContext.insert(sdModel)
        try modelContext.save()
    }

    func delete(id: UUID) throws {
        let descriptor = FetchDescriptor<FeatureSDModel>(
            predicate: #Predicate { $0.id == id }
        )
        if let sdModel = try modelContext.fetch(descriptor).first {
            modelContext.delete(sdModel)
            try modelContext.save()
        }
    }
}
```

## SwiftData Model Design

### Naming Convention

| Type | Naming | Location |
|------|--------|----------|
| SwiftData Model | `[Feature]SDModel` | `Data/[Feature]/Models/` |
| Domain Model | `[Feature]Model` | `Domain/[Feature]/Models/` |

### SwiftData Model Example

```swift
// Data/[Feature]/Models/FeatureSDModel.swift
import SwiftData

@Model
final class FeatureSDModel {
    @Attribute(.unique) var id: UUID
    var title: String
    var body: String
    var createdAt: Date
    var updatedAt: Date

    // Relationships
    @Relationship(deleteRule: .cascade)
    var comments: [CommentSDModel]?

    init(id: UUID = UUID(), title: String, body: String) {
        self.id = id
        self.title = title
        self.body = body
        self.createdAt = Date()
        self.updatedAt = Date()
    }

    convenience init(from model: FeatureModel) {
        self.init(id: model.id, title: model.title, body: model.body)
    }

    func update(from model: FeatureModel) {
        self.title = model.title
        self.body = model.body
        self.updatedAt = Date()
    }

    func toDomain() -> FeatureModel {
        FeatureModel(id: id, title: title, body: body)
    }
}
```

The SDModel ↔ Domain mapping lives in Data (on the SDModel, or in a `[Feature]SDModelMapper` protocol + Impl). Domain never references `FeatureSDModel`.

### Domain Model (Clean - No SwiftData)

```swift
// Domain/[Feature]/Models/FeatureModel.swift
struct FeatureModel: Sendable, Equatable, Identifiable {
    let id: UUID
    var title: String
    var body: String

    init(id: UUID = UUID(), title: String, body: String) {
        self.id = id
        self.title = title
        self.body = body
    }
}
```

## Schema Migrations

### Lightweight Migration (Automatic)

SwiftData handles simple changes automatically:
- Adding new properties with default values
- Removing properties
- Renaming (with `@Attribute(originalName:)`)

```swift
@Model
final class FeatureSDModel {
    @Attribute(.unique) var id: UUID
    var title: String
    var body: String
    var summary: String = ""  // New property with default
    @Attribute(originalName: "content") var body: String  // Renamed
}
```

### VersionedSchema (Breaking Changes)

For breaking changes, use versioned schemas:

```swift
// Data/Persistence/Migrations/FeatureSchemaV1.swift
enum FeatureSchemaV1: VersionedSchema {
    static var versionIdentifier = Schema.Version(1, 0, 0)

    static var models: [any PersistentModel.Type] {
        [FeatureSDModelV1.self]
    }

    @Model
    final class FeatureSDModelV1 {
        var id: UUID
        var title: String
        var content: String  // Old name
    }
}

// Data/Persistence/Migrations/FeatureSchemaV2.swift
enum FeatureSchemaV2: VersionedSchema {
    static var versionIdentifier = Schema.Version(2, 0, 0)

    static var models: [any PersistentModel.Type] {
        [FeatureSDModel.self]
    }
}

// Data/Persistence/Migrations/FeatureMigrationPlan.swift
enum FeatureMigrationPlan: SchemaMigrationPlan {
    static var schemas: [any VersionedSchema.Type] {
        [FeatureSchemaV1.self, FeatureSchemaV2.self]
    }

    static var stages: [MigrationStage] {
        [migrateV1toV2]
    }

    static let migrateV1toV2 = MigrationStage.custom(
        fromVersion: FeatureSchemaV1.self,
        toVersion: FeatureSchemaV2.self
    ) { context in
        // Custom migration logic
        let features = try context.fetch(FetchDescriptor<FeatureSchemaV1.FeatureSDModelV1>())
        for feature in features {
            // Transform data
        }
        try context.save()
    }
}
```

### Safe Migration Testing

```swift
// Tests: Always test migrations with real data
@Test func testV1toV2Migration() async throws {
    // 1. Create V1 container with test data
    // 2. Apply migration
    // 3. Verify data integrity in V2
}
```

## Anti-patterns to Avoid

### DO NOT

```swift
// ❌ Don't use @Query in ViewModels
@Observable
class FeatureViewModel {
    @Query var features: [FeatureSDModel]  // WRONG
}

// ❌ Don't access mainContext from background
Task.detached {
    let context = container.mainContext  // CRASH RISK
}

// ❌ Don't pass models between actors
await repository.save(featureSDModel)  // CRASH RISK

// ❌ Don't use SwiftData in Domain layer
// Domain/[Feature]/Models/FeatureModel.swift
import SwiftData  // WRONG - Domain should be pure Swift
```

### DO

```swift
// ✅ Use @Query only in Views (if needed)
struct FeatureListView: View {
    @Query var features: [FeatureSDModel]
}

// ✅ Create dedicated executor for background
let executor = DefaultSerialModelExecutor(modelContext: ModelContext(container))

// ✅ Pass IDs between actors
await repository.save(featureId: feature.id)

// ✅ Keep Domain layer pure
// Domain/[Feature]/Models/FeatureModel.swift
import Foundation  // Only Foundation
```

## Integration with Clean Architecture

### Layer Boundaries

```
┌─────────────────────────────────────────────────────────────┐
│  PRESENTATION                                                │
│  - Views may use @Query for read-only lists (optional)      │
│  - ViewModels work with Domain models only                  │
│  - No SwiftData imports in ViewModels                       │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│  DOMAIN                                                      │
│  - Pure Swift models (no SwiftData)                         │
│  - UseCases orchestrate repositories                        │
│  - No persistence framework imports                         │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────────────────────────────────────┐
│  DATA                                                        │
│  - SwiftData models ([Feature]SDModel)                      │
│  - Repositories use ModelExecutor                           │
│  - Map SD models ↔ Domain models                            │
│  - Handle migrations                                        │
└─────────────────────────────────────────────────────────────┘
```

### Dependency Flow

With the template enabled, `AppDependencies` (still in `App/Config/`, still a `struct`) gains a `swiftDataStack`, and the `@main` App creates the stack, passes it in, and attaches `.modelContainer(...)`. Factories read it from `AppDependencies`, exactly like `apiClient`; repositories are not stored in `AppDependencies` and dependencies are not put in `@Environment`.

```swift
// App/Config/AppDependencies.swift (generated with the SwiftData option)
struct AppDependencies {
    // MARK: - Properties

    let apiClient: APIClient
    let swiftDataStack: SwiftDataStack

    // MARK: - Init

    init(swiftDataStack: SwiftDataStack) throws {
        let configuration = try EnvironmentConfigurationImpl()
        apiClient = APIClientImpl(configuration: configuration)
        self.swiftDataStack = swiftDataStack
    }
}
```

`App/DI/PersistenceAssembly.swift` (also generated) offers `makeSwiftDataStack()`, `makePreviewSwiftDataStack()` and `makeExecutor(from:)` helpers.

## Testing SwiftData

### In-Memory Container for Tests

```swift
@Suite("[Feature]Repository Tests")
struct FeatureRepositoryTests {

    @Test func saveAndFetch() async throws {
        // Given
        let container = ModelContainer.preview
        let executor = DefaultSerialModelExecutor(
            modelContext: ModelContext(container)
        )
        let repository = FeatureRepositoryImpl(modelExecutor: executor, modelContainer: container)

        let feature = FeatureModel(title: "Test", body: "Content")

        // When
        try await repository.save(feature)
        let fetched = try await repository.fetchFeature(id: feature.id)

        // Then
        #expect(fetched?.title == "Test")
    }
}
```

### Mock Repository (No SwiftData in Tests)

```swift
// Tests/Mocks/MockFeatureRepository.swift
actor MockFeatureRepository: FeatureRepository {
    var features: [FeatureModel] = []

    func fetchFeature(id: UUID) async throws -> FeatureModel? {
        features.first { $0.id == id }
    }

    func save(_ model: FeatureModel) async throws {
        features.append(model)
    }
}
```

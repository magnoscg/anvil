# PROJECT-STRUCTURE.md — Folder Structure

Where each file goes in a project generated by anvil. The reasons behind the layers are in `ARCHITECTURE.md`.

Sources live in `[Project]/` (one app target) and tests in `[Project]Tests/`. Layers are folders, not modules.

```text

|  |  +- AppRouterImpl.swift            # Owns the NavigationPath (`path`)
|  |  +- AppNavigationCoordinator.swift # Deep links, state restoration, debounced save
```

## Placement Rules

- **Xcode project**: `[Project]/` and `[Project]Tests/` are file-system-synchronized groups, so new files are picked up automatically; never edit `project.pbxproj` to add them.
- **Naming**: every source file of a feature starts with the feature name and is named after its main type. Protocols take no `Protocol` suffix; implementations end in `Impl`.
- **One file or two**: UseCase and Repository keep protocol and `Impl` in separate files (the Repository protocol in Domain, its `Impl` in Data). DataSources, DTOMappers, DecoratorMappers and the Router keep protocol and `Impl` in one file, and the Route enum lives inside the Router file.
- **By concept**: `Domain/` and `Data/` are organized by domain concept. `anvil feature` starts with one folder per feature; merge them (for example `Domain/Article/`) when several screens share a concept. `Features/` stays one folder per screen.
- **Optional files** exist only when chosen in `anvil feature`: `LocalDataSource`, `KeychainDataSource`, `RouteResolver` and the UI-test set (`AccessibilityID`, `DataStubs/`, `UITests/`). Add a resolver only when the feature owns destinations, and register it in `App/Navigation/RootNavigationView.swift`.
- **Shared or local**: a view, modifier or builder used by more than one feature goes in `Core/Common/SwiftUI/`; a subview used by a single feature goes in its `UI/Components/`. Shared formatters go in `Core/Common/Extensions/`.
- **Tests** mirror the source tree. Mocks are shared in `[Project]Tests/Mocks/` and named `<Feature><Type>Mock.swift` (`testing.md`). UI tests, stubs and fixtures: `ui-testing.md`.

## What Each Layer May Use

Everything compiles in one target, so there is no `import` between layers and these limits are enforced by review.

| Layer | May use | Must not use |
| --- | --- | --- |
| `App/` | Every layer: it is the composition root | Business logic |
| `Core/` | Foundation, SwiftUI, system frameworks; `DomainError` only in `ErrorDecorator.from(_:)` | Feature types; Data types, except the SwiftData schema list in `Persistence/` (`swiftdata.md`) |
| `Domain/` | Foundation | SwiftUI, SwiftData, URLSession, `APIError`, DTOs, anything from Data or Features |
| `Data/` | Domain, Core (`Networking/`, `Security/`, `Persistence/`), SwiftData | SwiftUI, Presentation types |
| `Features/` | Domain, Core, SwiftUI | Data types; only the Factory in `DI/` builds them |

Step-by-step creation of a feature, with code: `new-feature.md`.
